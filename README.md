# 礼簿·人情记

微信小程序，使用微信云开发保存人情往来。当前可微信登录、设置昵称、建立多个账本、新增／修改／删除收送礼记录、查看整本账本统计、按日／按月查看并按姓名搜索、共享账本及管理成员和邀请码，还可导出当前账本的全部记录为 CSV。账本成员优先显示自己设置的昵称，并附账号标识尾号；加入共享账本的一方也能看到是谁分享的账本。界面分为“账本／往来／我的”三个底部页面，新增和编辑记录使用独立页面。权限细分、可选加密、AI 记账和提醒仍待开发。

## 当前部署步骤

本次调整：在“往来”中搜索姓名后，当前账本的人员卡片显示最近一次收礼、实际登记的最近一次回礼及待回礼笔数；点击收礼记录可点“记录回礼”，选择记入当前账本或自己名下的另一本账本，填写实际金额、日期和备注。若送礼早已登记，点“关联已有”即可关联，无需重复新增；误关联时在该笔送礼的编辑页点“解除回礼关联”，原记录和金额不会删除。收礼与回礼通过记录 ID 关联，不靠金额相抵判断；同一笔收礼可以追加多次回礼。“全部时间”的人员明细可查看自己其他账本中姓名完全相同的记录；按日／按月仅筛当前账本的原始记录，同时显示其关联回礼。跨账本回礼只允许相同账本主人，且操作人有权访问两本账本；共享成员目前只能记在当前共享账本。旧“已结清”记录仍显示为旧标记，但因没有回礼金额，不冒充实际回礼；可在明细中主动清除旧标记。请在 `entries` 集合添加非唯一索引 `returnForEntryId` 升序，再右键 `cloudfunctions/entries` 选择“上传并部署：云端安装依赖”，重新编译并用测试账本真机验证。跨账本关联目前不会由 CSV 导入自动重建，CSV 适合查阅和保存原始金额，不能当作完整关联关系备份。

此前版本曾支持逐笔勾选“已结清”；新版本已改为登记并关联实际回礼。旧记录的结清状态仍保留，不会删除或擅自生成回礼金额。CSV 导出仍含“状态”列，旧格式 CSV 仍可导入。

此前新增：共享成员可在“我的 → 当前账本”主动退出；“我的”可选择聊天中的 CSV 文件，先预览后确认导入（一次最多 500 笔）；“往来”按同一姓名归类。无日期记录显示“未知时间”，在按日或按月筛选时不出现，在“全部”中可见。姓名完全相同才归为一人，姓名相近不会自动合并。CSV 导入会新增记录，重复导入同一文件会产生重复记录；同一次导入中断后的“继续导入”不会重复写入已完成批次。

先在微信开发者工具中分别右键 `cloudfunctions/ledgers` 和 `cloudfunctions/entries`，选择“上传并部署：云端安装依赖”，确认使用正确云环境，再重新编译并真机测试。可先导出测试账本的 CSV，删除其中一行日期，在“文件传输助手”中发送给自己，再从“我的 → CSV 批量导入”选择该文件验证。请先使用测试账本，不要直接对真实账本重复导入。

本次调整仅涉及小程序页面：往来列表改为整条记录可点开编辑页，完整显示备注；删除入口移至编辑页并保留二次确认。重新编译小程序即可，云函数无需为本次界面调整重新部署。真机检查长姓名、长备注和小屏幕上的金额排版，点击记录后试验保存与删除返回列表。

本次新增记录添加人展示、加入共享账本前设置昵称，以及姓名拼音／首字母模糊搜索。先在微信开发者工具中分别右键 `cloudfunctions/entries` 和 `cloudfunctions/ledgers`，选择“上传并部署：云端安装依赖”，确认云环境正确，再重新编译小程序。`entries` 新增了 `pinyin-pro` 依赖，不能只上传代码而跳过云端安装依赖。现有记录不需要迁移；拼音搜索会读取所选账本和日期范围内的记录，最多支持 10000 笔，较大账本建议先按月筛选。无需新增数据库索引。

真机验证：大号和小号都在“我的”设置不同昵称，各新增一笔共享账本记录；双方进入“往来”，确认记录显示原添加人的昵称与尾号。用未设置昵称的账号输入邀请码，应跳转提示去“我的”保存昵称，返回后仍保留邀请码并可加入。搜索已有的“张三”记录时，分别试 `zhangsan`、`zs`、`san`，确认列表与统计同步变化。

本次新增账本改名与删除：先分别右键 `cloudfunctions/ledgers`、`cloudfunctions/entries`，选择“上传并部署：云端安装依赖”，再重新编译小程序。只有账本创建者可在“我的 → 当前账本”改名或删除；删除前必须完整输入“确认删除账本”。删除是逻辑删除：账本、记录、成员和邀请码会立即在小程序中失去访问入口，但原始数据仍暂存云端以防误删，目前没有自助恢复入口。请先导出重要账本，并用测试账本验证删除，不要用真实账本试验。

按钮采用统一的最小高度、内边距和水平／垂直居中；真机预览时请检查“新建、搜索、保存、邀请、导出”按钮的文字是否对齐。

本阶段新增“按日／按月与姓名筛选”。不新增集合，不修改已有记录；沿用 `entries` 的 `ledgerId + happenedOn + _id` 复合索引。在当前小程序使用的云环境中操作：

1. 右键 `cloudfunctions/entries` →“上传并部署：云端安装依赖”。确认选择的是当前小程序使用的云环境。
2. 在微信开发者工具重新编译；若云端提示缺少查询索引，在 `entries` 集合检查或建立 `ledgerId` 升序、`happenedOn` 降序、`_id` 降序的复合索引。不要删除原有索引或数据。
3. 需要小号验证时，点击“上传”，到微信公众平台将新开发版本设为体验版；小号扫体验版二维码，不能扫开发者工具的预览／真机调试码。

## 真机验证

先在同一本账本中准备不同日期、不同姓名的几笔记录。进入“往来”，依次切换“全部／按日／按月”，点击日期选择器选择指定日期；确认列表和收送礼统计同步变化。输入姓名的一部分并点击“搜索”，应只显示匹配该姓名的记录；可与日期条件叠加，点击“清除”恢复姓名筛选。记录超过 20 笔时，继续下拉加载也应遵守筛选条件。“我的 → 导出账本”仍导出整本账本，不受页面筛选影响。

1. 大号在“我的”页设置昵称；小号进入大号共享的账本，在“共享给我的”列表中确认显示“由大号昵称（尾号 …）共享”。选择该账本后，在当前账本、往来页和“我的”页也应能看到分享者。大号修改昵称后，小号在“账本”页下拉刷新可更新显示；未设置昵称时应显示“账本主人（尾号 …）”。
2. 大号和小号分别设置不同昵称；大号进入所拥有账本的“我的”页，检查成员列表显示小号昵称及账号尾号。小号修改昵称后，大号重新进入“我的”页或下拉刷新，确认成员列表更新。
3. 在“账本”页切换账本，确认“往来”和“我的”都显示对应的账本；点击“记一笔”，保存后返回记录列表，编辑和删除也应正常。刷新或重开小程序后，当前账本仍保持选择。
4. 在“我的”页验证邀请码、成员管理；用共享成员账号确认能记账和导出，但不能管理邀请码或成员。不同微信号的当前账本选择互不混用。
5. 打开有两笔以上收／送礼记录的测试账本，在“我的”页点击“生成导出文件”，确认进度和最终笔数。点击“发送导出文件”，将 CSV 发给自己的“文件传输助手”。
6. 在电脑上下载并用表格软件打开，检查中文、日期、收送方向、金额两位小数和备注；确认不是仅导出了页面当前加载的前 20 笔。
7. 返回小程序点击“清除本地导出文件”，确认发送按钮消失。已经发送到聊天中的文件不会因此删除，请自行管理。
8. 用共享成员账号重复导出，确认仅能导出有权限的账本；被移除后不应再能导出。空账本应生成只有表头的 CSV。

若导出提示“未知记账操作”，先确认新版 `entries` 云函数已部署到当前环境。文件发送功能需在手机微信中真机测试，开发者工具模拟器不能代替这一步。

若账本主人曾将某成员“移除”，新邀请码也不能让该成员自行重新加入。这是成员权限规则，不是邀请码过期；账本主人应在“我的 → 账本成员”找到该成员并点击“恢复”，对方无需再输入邀请码。新版页面会分别提示“已移除”“邀请码过期”和网络错误。

导出文件在手机本地生成，不上传到云存储；它是**未加密**的 CSV，发送到聊天后也会存在聊天记录中。当前手机端最多导出 10000 笔；若超过上限会拒绝生成文件，不会静默截断。导出期间若其他成员同时增删记录，可能需要重试以取得一致结果。

## 数据结构

- `users`：OpenID 为 `_id`，首次登录创建；`nickname` 为用户自行设置的昵称。
- `ledgers`：`name`、`ownerOpenid`、创建与更新时间。
- `entries`：`ledgerId`、`createdByOpenid`、`direction`（`received`/`given`）、`personName`、`amountFen`、`happenedOn`（`YYYY-MM-DD`）、`note`、创建与更新时间。
- `ledgerMembers`：确定性 `_id`、`ledgerId`、`memberOpenid`、`role`、`status`（移除／恢复状态）、加入时间。
- `ledgerInvites`：随机 32 位邀请码为 `_id`、`ledgerId`、邀请人 OpenID、到期时间、`revoked`（撤销状态）。

身份来自云函数中的微信上下文，不信任前端传入的 OpenID。`entries` 云函数在每次读写及统计前验证用户是账本所有者或**未被移除**的编辑成员；修改和删除还会验证目标记录属于该账本。邀请码由所有者生成，服务端校验有效期、撤销状态与账本归属。

导出通过 `entries` 云函数按账本分页读取，仍进行同样的权限检查。前端生成带 UTF-8 BOM 的 CSV；往来对象与备注中的逗号、引号和换行会转义，以 `= + - @` 开头的内容会被当作普通文本而非表格公式。

## 同步到 GitHub

项目可以使用 Git 同步到 GitHub。`.gitignore` 已排除微信开发者工具的本机私有配置、依赖安装目录、日志和常见密钥文件。`project.config.json` 中的 AppID 与 `miniprogram/app.js` 中的云环境 ID 仍会进入仓库；它们不是登录密钥，但建议先使用**私有仓库**。

新建空的 GitHub 私有仓库时，不要在网页端勾选 README、`.gitignore` 或许可证。取得仓库 URL 后，在项目目录执行 `git remote add origin <仓库URL>` 和 `git push -u origin main`。不要把云数据库导出的真实人情数据提交到仓库。
