# 礼簿·人情记

一款已上线的微信小程序，面向婚礼、酒席等场景记录收礼与送礼，并帮助用户查找同一人的历史往来。项目采用微信小程序原生技术和微信云开发；本仓库只包含源码与测试，不包含线上账本数据。

> 简历项目说明：这是一个实际使用的产品，不是静态页面演示。当前版本聚焦多账本、共享协作、往来查询、回礼关联和 CSV 导入导出；账本加密、AI 记账和提醒仍在规划中。

## 功能概览

| 场景 | 已实现的能力 |
| --- | --- |
| 账本管理 | 创建多个账本、改名、输入确认文字后逻辑删除、记住当前选择 |
| 日常记账 | 收礼／送礼记录的新增、编辑、删除；金额以“分”存储；日期可留空并显示“未知时间” |
| 往来查询 | 按人归类、按日／月筛选、姓名及拼音模糊搜索、统计收送礼金额 |
| 回礼跟踪 | 将实际送礼记录关联到原收礼记录；支持多次回礼及同一主人名下的跨账本关联；保留旧“已结清”标记但不伪造回礼金额 |
| 共享协作 | 24 小时邀请码、成员加入／退出、主人移除／恢复成员；记录显示原添加人昵称 |
| 数据迁移 | CSV 批量导入前预览，分批提交并支持中断后继续；按账本权限导出 CSV |

## 技术设计

- 小程序端：原生 JavaScript、WXML、WXSS，使用三个底部页面组织账本、往来和个人设置。
- 服务端：`login`、`ledgers`、`entries` 三个云函数；身份取自微信云函数上下文，不接受前端传来的 OpenID 作为授权依据。
- 数据层：CloudBase 文档型数据库，使用 `users`、`ledgers`、`entries`、`ledgerMembers`、`ledgerInvites` 五个集合。
- 权限：每次账本读写先验证所有者或有效共享成员，再校验目标记录所属账本；跨账本回礼还验证两本账本的访问权。
- 工程处理：金额转整数分避免浮点误差；CSV 做引号转义与表格公式防护；导入批次使用稳定 ID 避免中断重试重复写入。

## 本地运行与测试

1. 准备微信小程序 AppID、微信开发者工具和自己的云开发环境。
2. 克隆仓库并导入项目。**先将 `project.config.json` 的 AppID 与 `miniprogram/app.js` 的云环境 ID 换成自己的值，不要直接连接此项目的线上环境。**
3. 按 [部署清单](docs/DEPLOYMENT.md) 建立集合、权限与索引，并部署三个业务云函数。
4. 编译小程序，用测试账本走通登录、记账、共享、回礼和 CSV 导入导出。

本地测试需先安装 `entries` 云函数依赖，然后在仓库根目录运行：

```bash
pnpm --dir cloudfunctions/entries install --frozen-lockfile
node --test tests/*.test.js
```

GitHub Actions 会在推送和拉取请求时运行同一组测试。测试使用模拟的微信云开发接口，不能替代云端权限检查和真机回归。

## 当前边界

- CSV 是查阅和迁移原始记录的文件，**不是完整备份**：重新导入不会恢复回礼关联；导出文件未加密。请另行配置云数据库备份。
- 一次 CSV 导入最多 500 笔；搜索和手机端导出目前最多处理 10,000 笔，大账本建议按月查询。
- 账本删除为逻辑删除，当前没有用户自助恢复入口；单条往来记录删除没有回收站。
- 共享成员目前是可读写的编辑成员，尚未提供只读角色；端到端加密、AI 记账和提醒尚未实现。
- 仓库中的 AppID、云环境 ID 是资源标识，不是密钥；真正的数据隔离依赖云数据库权限与云函数服务端鉴权。部署时务必使用自己的环境。
