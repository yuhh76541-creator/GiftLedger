# 架构与数据约束

## 请求链路

小程序页面通过 `wx.cloud.callFunction` 调用业务云函数。`login` 创建或更新当前用户资料；`ledgers` 管理账本、共享成员和邀请码；`entries` 处理往来记录、统计、搜索、回礼关联和导入导出。云函数从 `getWXContext().OPENID` 获取身份，服务端检查账本访问权，不依赖页面传入的用户标识。

## 数据模型

| 集合 | 关键字段与用途 |
| --- | --- |
| `users` | 以 OpenID 为 `_id`，保存用户自行设置的昵称 |
| `ledgers` | 账本名称、主人 `ownerOpenid`、创建时间、逻辑删除时间 |
| `entries` | `ledgerId`、方向、姓名、整数分金额、可为空的日期、备注、添加人；回礼使用 `returnForEntryId` 与 `returnForLedgerId` 指向原收礼 |
| `ledgerMembers` | 账本与成员、编辑角色，以及 `active`／`removed`／`left` 状态 |
| `ledgerInvites` | 邀请码、账本、过期时间和撤销标记 |

同名往来在列表中归为一人，但不会自动合并底层记录。拼音查询在云函数中扫描符合账本和日期范围的记录，因此对大账本设置了 10,000 笔上限。

## 回礼语义

收礼和回礼以记录 ID 关联，不用“收礼减送礼”计算状态。同一笔收礼可以关联多笔实际送礼，每笔金额和日期都保留。旧版本手动勾选的 `settled` 标记仍可显示，但没有实际回礼金额，不会伪造成回礼记录。

账本主人可以把回礼记在自己名下的另一本账本；共享成员只能在当前共享账本内操作。读取跨账本关联前会验证调用者对相关账本的权限。

## 导入与导出

导入先在手机端解析、校验并预览 CSV，再按 20 笔一批调用云函数。同一次导入中断后使用相同批次编号重试，服务端用确定性记录 ID 避免重复；再次选择同一文件启动新导入仍会新增记录。

导出按账本分页读取，在手机端生成 UTF-8 BOM CSV，并区分实际登记回礼、旧结清标记和普通送礼。CSV 不保存可重建的跨记录关联，不能替代数据库备份。
